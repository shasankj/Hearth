# Go

## Core concepts
- **Compiled, statically typed, garbage collected, one static binary.** No classes or inheritance: **structs + methods + interfaces + composition**.
- **Zero values:** every type has a usable default (`0`, `""`, `nil`). A `nil` map panics on write; a `nil` slice is fine to `append`.
- **Errors are values.** Functions return `(result, error)`; you check `if err != nil`. Wrap with `fmt.Errorf("...: %w", err)`; inspect with `errors.Is` (match a specific error) and `errors.As` (match a type).
- **Slices** = (pointer, len, cap) over an array. `append` may allocate a bigger array (cap roughly doubles), so always `s = append(s, x)`. Sub-slices share memory (mutating one mutates the other).
- **Maps:** unordered, reference type, **not safe for concurrent writes** (use a mutex or `sync.Map`).
- **Interfaces are implicit:** a type satisfies an interface just by having the methods. "Accept interfaces, return structs."
- **Pointer vs value receivers:** pointer receiver to mutate or avoid copying big structs; value receiver for small read-only types. Don't mix on one type.
- **`defer`** runs at function return, LIFO; used for unlock/close. **`panic/recover`** is for truly exceptional cases, not control flow.
- **Packages and modules:** `go.mod` defines the module; lowercase names are unexported (private).

## Concurrency (the most-asked area)
- **Goroutine:** lightweight (≈2 KB stack, grows), scheduled by the Go runtime onto OS threads (**G-M-P model**: Goroutines, Machine threads, Processors/run-queues; work stealing).
- **Channels:** typed pipes. Unbuffered = rendezvous (sender blocks until receiver ready). Buffered = queue. `close(ch)` signals "no more"; receiving from closed gives zero values (`v, ok := <-ch`). `select` waits on multiple channels.
- **Sync primitives:** `sync.Mutex`, `sync.RWMutex` (many readers or one writer), `sync.WaitGroup`, `sync.Once`, `sync/atomic`.
- **`context.Context`:** carries cancellation, deadlines, request-scoped values. First parameter of any function that does I/O. Always call `cancel()` (`defer cancel()`).
- **Data race:** two goroutines access the same memory, one writes, no synchronization. Detect with `go test -race`.
- **Goroutine leak:** a goroutine blocked forever (e.g. sending on a channel nobody reads). Always give goroutines a way to exit (context or closed channel).

Worker-pool pattern (know this by heart):
```go
func process(jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
	defer wg.Done()
	for j := range jobs { results <- j * 2 }
}
// start N workers, send jobs, close(jobs), wg.Wait(), close(results)
```
`errgroup.Group` (golang.org/x/sync) = WaitGroup + first-error + context cancellation.

## Advanced
- **Scheduler:** goroutines blocked on I/O are parked, the thread runs another; since 1.14 preemption is asynchronous.
- **GC:** concurrent tri-color mark-and-sweep; tuned by `GOGC` and `GOMEMLIMIT`. Reduce allocations to reduce GC (reuse buffers, `sync.Pool`, preallocate slices `make([]T, 0, n)`).
- **Escape analysis:** the compiler decides stack vs heap (`go build -gcflags=-m`).
- **Generics (1.18+):** `func Map[T, U any](xs []T, f func(T) U) []U`. Use for containers/utilities, not everywhere.
- **Interface gotcha:** an interface holding a nil *pointer* is **not** `== nil` (it has a type). Return a literal `nil` for "no error".
- **Testing:** table-driven tests, `t.Run` subtests, `t.Cleanup`, `-race`, `-cover`, benchmarks (`b.N`), fuzzing. Profiling: `pprof` (CPU, heap, goroutine, block).
- **Production habits:** graceful shutdown, deadlines on every outbound call, structured logging, health endpoints, no global mutable state.

## Code walkthrough (this repo): [services/listing](../services/listing)
**[repo.go](../services/listing/repo.go)**: the `Repo` interface hides storage, so the gRPC server never sees SQL and can be tested with a fake. `ErrNotFound` is a **sentinel error** returned by the repo; the transport layer converts it to a gRPC code (separation of concerns).

**[query.go](../services/listing/query.go)**: builds the search SQL safely.
- `builder.add(cond, args...)` replaces each `?` with the next `$n` placeholder and records the arg: **values never get concatenated into SQL** (prevents injection).
- `orderBy` is a **whitelist map**: user-supplied `sort` picks a constant string, unknown values fall back to `newest`. A unit test passes `x'; DROP TABLE listings; --` and asserts it never reaches the SQL text.
- Each filter group is its own method (`status`, `text`, `numeric`, `minimums`, `lists`, `geo`) so every function stays ≤ 10 lines and is easy to test.
- `COUNT(*) OVER()` returns the total count in the same query (no second round trip).
- `previous_price_usd` comes from a correlated subquery over `price_history` (drives the "price drop" badge without denormalizing).

**[model.go](../services/listing/model.go)**: `dbListing` carries `db:"..."` tags; `pgx.RowToStructByName` maps columns to fields, so there is no hand-written `Scan(&a, &b, …)` list. `toPB` converts to the protobuf type in three small functions.

**[pgrepo.go](../services/listing/pgrepo.go)**: `pgxpool` (connection pool). `Get` loads the listing, its agent and price history. `Similar` finds same city/status/type within ±30% price ordered by closeness. `Market` uses `percentile_cont(0.5)` for the median. It works unchanged against **AWS RDS** (only the URL differs).

**[server.go](../services/listing/server.go)**: validates input (status whitelist, query length), caps page size, `toStatus` maps `ErrNotFound → NOT_FOUND` and everything else to a generic `INTERNAL` (details only in logs). `StreamListings` pages through all results and streams them (server streaming).

**[main.go](../services/listing/main.go)**: `mustPool` retries the DB connection (the database may start after us in Compose/Kubernetes); `logInterceptor` is gRPC middleware; `shutdownOnSignal` calls `GracefulStop`.

**Tests**: [query_test.go](../services/listing/query_test.go) (pure) and [pg_test.go](../services/listing/pg_test.go) (**integration against real Postgres**, skipped unless `TEST_DATABASE_URL` is set; in-memory `bufconn` gRPC server for status codes and streaming).

## Interview Q&A
**Q: Goroutine vs thread?** Goroutines are user-space, ~2 KB initial stack, cheaply multiplexed by the Go scheduler onto few OS threads; you can run hundreds of thousands. Threads are OS-scheduled, MB stacks, expensive context switches.

**Q: Buffered vs unbuffered channel?** Unbuffered synchronizes sender and receiver. Buffered decouples up to N items; sender blocks only when full. Use unbuffered for handoff/ordering guarantees, buffered for bursts or bounded work queues.

**Q: How do you stop a goroutine?** Pass a `context` (or a `done` channel) and have it `select` on `ctx.Done()`.

**Q: What's wrong with `for i := 0; i < 3; i++ { go func(){ fmt.Println(i) }() }`?** Before Go 1.22 all goroutines shared one `i` (usually printed 3,3,3). Since 1.22 each iteration has its own `i`. Pass as argument to be safe.

**Q: Mutex vs channel?** "Share memory by communicating." Channels for ownership transfer and pipelines; mutex for protecting shared state (simple counters, caches). Don't force one.

**Q: How do you handle errors across layers?** Wrap with `%w` adding context at each layer, define sentinel/typed errors at domain boundary, translate to transport codes (HTTP/gRPC) at the edge. Don't log *and* return.

**Q: Why did `append` need reassignment?** It returns a new slice header; if capacity was exceeded the data lives in a new array.

**Q: `new` vs `make`?** `new(T)` returns `*T` zeroed. `make` creates slices, maps, channels (initialized internal structures).

**Q: How would you make a map safe for concurrent use?** `sync.RWMutex` around a map (usually best), or `sync.Map` for write-once/read-many or disjoint keys.

**Q: How do you find a memory leak / slow code?** `pprof` heap/CPU profiles, goroutine dump for leaks, `-race`, benchmarks.

**Q: Why Go for services here?** Fast startup, small static binaries, strong concurrency, first-class gRPC/Temporal SDKs, simple deploys (distroless/alpine images).
